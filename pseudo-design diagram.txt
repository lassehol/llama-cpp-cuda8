
Mapping out design components 
I’m sketching a pseudo-design diagram for cuBLAS GEMM acceleration, custom CUDA kernels, pinned memory with async copies, and stream-based execution, focusing on non-time-sensitive technical details. Love the thought experiment. Below are four pseudo‑design diagrams that show how a CUDA‑8.0‑era cpu‑llama.cpp could have used a GTX 560 (Fermi, CC 2.1) to accelerate inference, focusing on:
1) Basic cuBLAS GEMM acceleration
2) Custom CUDA kernels for quantized matmul
3) Pinned memory + async copies
4) Stream‑based execution


Notes for the Fermi era: no Tensor Cores, no WMMA, no DP4A; rely on FP32 cuBLAS and simple integer kernels; aim to preload weights in VRAM, stream activations, and overlap transfers with compute.




1) Basic cuBLAS GEMM Acceleration
Block/flow design
+---------------------+       +---------------------+         +---------------------+
|  LLM Graph Builder  |-----> |  Op Scheduler       | ----->  |  CUDA Backend       |
|  (CPU)              |       |  (CPU)              |         |  (GPU)              |
+---------------------+       +---------------------+         +---------------------+
       |                               |                               |
       | [Linear layer: Y = X·W + b]   |                               |
       v                               v                               v
+---------------------+       +---------------------+         +---------------------+
|  Host Buffers       |       |  cuBLAS Handle      |         |  Device Buffers     |
|  (FP32 activations) |       |  (cublasCreate)     |         |  (W preloaded, X,Y) |
+---------------------+       +---------------------+         +---------------------+
       |                               |                               |
       | H2D: X --> (cudaMemcpyAsync)  | cublasSetStream(streamGEMM)    |
       |                               | cublasSgemm(...)               |
       | D2H: Y <-- (cudaMemcpyAsync)  |                               |
       v                               v                               v
+---------------------+       +---------------------+         +---------------------+
|  Next CPU ops       |<------|  Events/Synchronize |<--------|  GPU Compute        |
+---------------------+       +---------------------+         +---------------------+


Key design choices (Fermi + CUDA 8.0)

Data types: FP32 for both inputs and accumulation. (FP16 compute not viable on Fermi; FP16 can be storage-only if carefully handled on CPU.)
Weight placement: Preload W to device global memory at model load; keep it resident to avoid PCIe thrash.
GEMM calls: Use `cublasSgemm` for X·W and then a tiny CUDA kernel to add bias b.
Batching: Prefer batched GEMM when generating multiple tokens or doing prompt processing to amortize kernel launch overhead.


2) Custom CUDA Kernels for Quantized Matmul
Kernel tiling & dequantization (int8 / q4_naïve)
(No DP4A on Fermi—use plain integer multiply-accumulate, accumulate in FP32)
Host (CPU)
  ├─ Quantize W -> W_q (int8 or 4-bit packed) + scales per block
  └─ Upload W_q, scales to GPU once

Device (GPU)
  ┌────────────────────────────────────────────────────────────────────┐
  │ __global__ qmm_kernel(X_fp32, W_q, scales, Y_fp32, M,N,K)          │
  │   // Tiled matmul:                                                  │
  │   // 1) Load tile of X into shared memory (fp32)                    │
  │   // 2) Load packed W_q tile + per-block scales                     │
  │   // 3) Dequantize on-the-fly into registers:                       │
  │   //    w_fp32 = scale[b] * dequantize(W_q_tile)                    │
  │   // 4) Accumulate: y += x * w_fp32 (FP32 accumulation)             │
  │   // 5) Write back Y tile to global memory                          │
  └────────────────────────────────────────────────────────────────────┘


Memory layout (W quantized, scales per block)
Global Memory (GPU)
  [ W_q blocks ]:  [ W_q(b0) ][ W_q(b1) ][ W_q(b2) ] ... [ W_q(bN) ]
  [ scales ]:      [ s(b0)   ][ s(b1)   ][ s(b2)   ] ... [ s(bN)   ]
  [ X ]:           activations tile-streamed
  [ Y ]:           outputs
Shared Memory (per block)
  [ tile_X_fp32 ]  [ tile_W_q + tile_scales ] ==> dequantize to registers


When to prefer custom kernels over cuBLAS

If weights are quantized and you want to avoid full dequantization to FP32 in VRAM (memory footprint + PCIe bandwidth).
For small tiles or irregular shapes where cuBLAS overhead dominates.


3) Pinned Memory + Async Copies (Double/Triple Buffering)
Host–device pipeline with page-locked buffers
Host (CPU)
+-----------------------------------+     +-----------------------------------+
| Pinned Buffer A (cudaHostAlloc)   |     | Pinned Buffer B (cudaHostAlloc)   |
|  - next input X_A                 |     |  - next input X_B                 |
+-----------------------------------+     +-----------------------------------+
         | H2D (streamH2D)                        | H2D (streamH2D)
         v                                        v
Device (GPU)
+----------------------+     +----------------------+     +----------------------+
| Device Buffer A      |     | Device Buffer B      |     | Device Buffer C      |
|  - X_A               |     |  - X_B               |     |  - Y (previous)      |
+----------------------+     +----------------------+     +----------------------+
      | Compute (streamGEMM)        | Compute (streamGEMM)      | D2H (streamD2H)
      v                              v                          v
+-----------------------------------+     +-----------------------------------+
| Pinned Out Buf C (cudaHostAlloc)  |<----| [Async D2H Y]                     |
+-----------------------------------+     +-----------------------------------+


Design notes

Use `cudaHostAlloc()` or `cudaHostRegister()` on CPU buffers to enable DMA‑friendly transfers.
Perform `cudaMemcpyAsync()` on dedicated H2D/D2H streams to overlap transfers with compute.
Maintain A/B/C buffer ring: while GPU computes on A, prefetch B; while B computes, C returns results to CPU.
Place events at the end of each async copy/compute to drive the scheduler without blocking.


4) Stream‑Based Execution (Overlapped Pipeline)
Timeline (ASCII Gantt)
Time ─────────────────────────────────────────────────────────────────────────>

streamH2D:   H2D(X_A) ──────────┐           H2D(X_B) ──────────┐         H2D(X_C) ────────┐
                                v                               v                          v
streamGEMM:           GEMM(X_A·W) ────────────────┐   GEMM(X_B·W) ────────────────┐   GEMM(X_C·W) ─────
                                                    v                               v
streamBias:                 add_bias(Y_A) ───┐            add_bias(Y_B) ───┐             add_bias(Y_C) ──
                                              v                             v
streamD2H:                             D2H(Y_A) ──────────┐           D2H(Y_B) ──────────┐      D2H(Y_C) ─
                                                         v                               v
CPU post:                                       sample/next-token_A     sample/next-token_B      ...


Stream wiring & synchronization

Streams:streamH2D for host→device input activations
streamGEMM for GEMM (cuBLAS handle bound via cublasSetStream)
streamBias for small post‑ops (bias add, residual add)
streamD2H for device→host outputs
Events:eventX_A_ready recorded on streamH2D, waited by streamGEMM before GEMM.
eventY_A_ready recorded on streamBias, waited by streamD2H before copy back.
No global sync: only event‑based local waits to keep the pipeline saturated.


Putting it together (pseudo‑orchestration)
Init:
  - Create cublasHandle; cublasSetStream(streamGEMM)
  - cudaStreamCreate(streamH2D), cudaStreamCreate(streamGEMM),
    cudaStreamCreate(streamBias), cudaStreamCreate(streamD2H)
  - Upload quantized or FP32 weights to device once

Per iteration (token or micro-batch):
  1) Host writes X into the next pinned buffer slot (A/B/C)
  2) H2D: cudaMemcpyAsync(X_host_slot → X_dev_slot, streamH2D); record eventX_ready
  3) GEMM: streamGEMM waits eventX_ready; run cublasSgemm or qmm_kernel
  4) Bias/Res: streamBias waits GEMM completion event; launch add_bias kernel
  5) D2H: streamD2H waits bias completion event; cudaMemcpyAsync(Y_dev_slot → Y_host_slot)
  6) CPU consumes Y_host_slot (sampling/next layer preparation) while GPU advances next slots




Practical constraints & tuning targets (Fermi)

PCIe 2.0 x16 bandwidth is limited—reduce host↔device traffic:Keep W on device; stream only activations.
Favor batched GEMM where possible.
Occupancy vs. shared memory:Choose tile sizes that fit Fermi shared memory (48 KB/block typical); avoid register spills.
Kernel launch overhead:Bundle small ops (bias/residual) or fuse where sensible to reduce launches.
Quantization trade‑offs:int8/q4 saves bandwidth/VRAM, but without DP4A expect modest gains; still useful for throughput if well‑tiled.
